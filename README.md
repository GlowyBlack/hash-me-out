# Book Review & Recommendation Platform

A full-stack web application built with FastAPI (backend) and Next.js (frontend).  
The system provides book search, ratings, reviews, reading lists, admin tools, and both content-based and personalized recommendation engines.  
It includes full Docker support using docker-compose and separate Dockerfiles for backend and frontend.

---

## Overview

This project is a complete book discovery platform designed for scalability, modularity, and real-world deployment.  
It integrates external APIs for genre enrichment, implements dataset sharding for performance, and provides personalized recommendations based on user behavior.

---

## Key Features

### Book Search & Discovery
- Fast search with filters (title, author, genre, publication year)
- Live search dropdown connected to backend
- Detailed book pages showing metadata, images, reviews, and average ratings
- Similar Books sidebar generated by the recommendation engine

### User Features
- Rating system (1–10)
- Review creation and display
- Up to 10 reading lists per user with full CRUD support
- Ability to request missing books
- Personalized recommendations based on user activity

### Authentication
- OAuth2 authentication using JWT
- Secure password hashing
- Admin and regular user roles

### Admin Dashboard
- Manage books (edit, add, delete)
- Manage users (suspend, unsuspend)
- Review moderation tools
- System activity monitoring

## Recommendation System

### Content-Based Book-to-Book Recommender
- Uses TF–IDF vectors built from title, author, and enriched genres
- Computes cosine similarity between books
- Excludes the target book from results
- Uses caching to improve repeated performance
- API endpoint:  
  `GET /recommendation/{isbn}`

### Personalized User Recommender
- Builds a weighted user preference vector using:
  - Ratings
  - Reviews
  - Reading list additions
  - Long-duration page views
- Returns the top 10 recommended books
- API endpoint:  
  `GET /personalized`

## Dataset Architecture and Efficiency

### CSV Sharding
The BX-Books dataset (~300k rows) is split into multiple shards based on the first letter of the title.  
This significantly improves read and write performance.

### Thread-Safe CSV Repositories
All read/write operations use concurrency locks to protect against data corruption.

### DataManager Singleton
Centralized manager for:
- Caching
- Shard indexing
- Safe, consistent data access

### BookAdapter Pattern
- Provides a unified interface for loading and interpreting book data from CSV files.  
- Handles differences in encoding and formatting across various CSV sources.  
- Normalizes fields before they enter the service layer, ensuring consistent internal representation.  
- Reduces coupling by isolating CSV parsing and transformation logic from services and routers.  
- Allows future CSV format changes without requiring modifications to other parts of the system.


### External API Integration
- **OpenLibrary API** – Used to enrich books with missing genre and metadata.  
- **PurgoMalum API** – Used to check for profanity in user reviews and support warning logic.

# Docker Deployment

This project includes:
- `docker-compose.yml`
- `backend/Dockerfile`
- `frontend/Dockerfile`

### Running the Application via Docker Compose

From the project root:

```bashdocker compose up --build ```

This builds both images, starts backend and frontend services, and configures their network.

### Accessing the Application

Frontend:  
`http://localhost:3000`

Backend API Documentation (Swagger):  
`http://localhost:8000/docs`

## Running Without Docker

### Backend (FastAPI)

```bash
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload
```
### Frontend (Next.js)
```bash
cd frontend
npm install
npm run dev
```
